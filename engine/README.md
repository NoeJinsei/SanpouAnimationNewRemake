WHAT TO BUILD
engine/vcanvas.js defining window.VCanvas, and engine/boot-canvas.js containing only:  window.HeroCanvas = VCanvas.create(window.JourneyPort);
VCanvas.create(JP) returns { scenes: { world, transit, network }, ready, stats() } where each scene function calls the matching JP._scenes function to get the virtual-node tree and paints that tree on the canvas, so that the result looks the same as the browser's own rendering of the tree. The engine is a general painter for the vocabulary the scene code uses, NOT a re-drawing of the scenes: it must not contain scene-specific knowledge (no hard-coded element positions), because the remake's upgraded art will be authored in the same h() vocabulary and must run through it unchanged.

Vocabulary to support = everything the three original scenes emit with JX_CLEAN_HERO = true. Find the full list yourself by reading original/js/hero-port-b.js end to end (including CoverageMap / LabelPlate / AnimatedRoute, mapInit, the Airport, the jet) and by walking real trees at many frames. It includes at least:
- HTML: div with style strings: position/inset/left/top/width/height, background as a colour, as linear-gradient(to bottom, stops...) and as one or several comma-separated radial-gradient(W% H% at X% Y%, stops...) / radial-gradient(ellipse W% H% at X% Y%, stops...), opacity, transform (scale(), translate(), translateX(), translateY()) with transform-origin in percent, overflow:hidden, mask-image: radial-gradient(...) (the map wrapper fades out toward its edges), and nested inline svg with width/height/viewBox and style position/inset.
- SVG: svg, g (transform strings: translate, scale with one or two values, rotate with optional centre, in any order and nesting; opacity; clip-path:url(#id)), defs, clipPath (rect children), linearGradient / radialGradient with stops (stop-color as rgba()/hex, stop-opacity) referenced by fill="url(#id)" - note the default gradientUnits is objectBoundingBox, so the gradient is positioned by the bounding box of the shape that uses it -, rect (rx), circle, ellipse, line, polygon, path (full path syntax incl. arcs; fill-rule default nonzero), text (x, y, font-family, font-size, font-weight, fill, letter-spacing, text-anchor), and the presentation attributes fill, stroke, stroke-width, stroke-dasharray, stroke-dashoffset, stroke-linecap, stroke-linejoin, opacity, fill-opacity, stroke-opacity, transform on any element. SVG defaults and INHERITANCE apply: fill defaults to black and is inherited from ancestor g elements (the forklift inside the warehouse uses <g fill="...">), stroke defaults to none, an element with opacity < 1 that has several children must be composited as ONE picture (clouds are a group of overlapping lobes at opacity ~0.88: painting each lobe with alpha would show the overlaps; render the group to a scratch surface and lay it over, limited to the group's bounds when you can work them out), attributes "0"/false/missing behave as in SVG. Elements with display:none style or zero opacity are skipped.
- Text: fonts are "Noto Sans JP" (loaded by the page; wait for it in ready with document.fonts.load for weights 400/700/800 with the Japanese sample text) and "Archivo" which is NOT loaded on the site and falls back to sans-serif - reproduce what the browser does. letter-spacing: use ctx.letterSpacing where available, else place glyphs yourself.

Performance design (this decides whether canvas is worth choosing, so do it properly):
- No per-frame parsing of anything that was parsed before: cache parsed transforms by string, Path2D by path string (bounded caches), parsed style strings, gradients.
- Memoised sub-trees: the scene code returns the SAME node object again for static parts (CityBuilding, UtilityPoles, VendingPair, gantries are memoised in the original). Use node identity to skip re-work where it is safe.
- Layer hints for the remake (opt-in, absent in the original): a <g> carrying  data-cache="key"  and  data-box="x y w h"  (stage units, in the group's own coordinate space) asks the engine to render that group once into an offscreen canvas at the current res and afterwards just draw the bitmap with the group's current transform/opacity, re-rendering only when the key string or res changes. Implement it, bound the memory (LRU, e.g. <= 64 MB of pixels), and prove it with a small test page of your own under engine/ (e.g. engine/test-cache.html) that shows a cached group is pixel-identical to the uncached one and how much time it saves.
- Blend and blur for the remake (opt-in, absent in the original): style "mix-blend-mode: screen|multiply|overlay|soft-light" on a g or shape maps to globalCompositeOperation; attribute  data-blur="px"  on a cached group blurs the cached bitmap once (ctx.filter where supported, with a documented fallback such as a down-scale/up-scale pass, because Safari has had no ctx.filter). These must also behave sensibly in the DOM renderer (mix-blend-mode is plain CSS there; data-blur can be ignored by DOM for now) - just make sure unknown attributes never break anything.
- stats() returns counters for the last frame: nodes visited, shapes painted, groups composited offscreen, cache hits/misses, path cache size.

Code style: one self-contained file, an IIFE, plain JavaScript that runs without a build step in current Chrome, Safari 16+ and Firefox; clear names; a header comment that states what is supported and what is deliberately not; comments only where the reason is not obvious.
